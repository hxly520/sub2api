消费积分与签到奖励

成功消费形成积分，次日签到有机会获得余额奖励

积分用于记录账户持续使用情况。系统只统计已成功结算的余额消费，不把充值、失败请求、退款或冻结金额当成有效消费。

10:1默认每消费 1U 形成 10 积分，实际比例以当日策略为准
00:05默认在次日结算前一自然日的成功消费
自然日昨日范围为 00:00 至 24:00，不跨天累计签到资格
每日一次签到开启且满足资格时，当天只能领取一次
最高 10%
活动奖励上限按昨日实际消费金额计算

满足签到条件时，余额奖励最高可达昨日实际消费金额的 10%。具体资格、随机结果和到账金额以当日积分中心显示及生效策略为准，并非每次签到固定获得 10%。

如何查看和签到

  1. 登录后从左侧菜单打开“积分中心”，查看总积分、昨日积分和消费曲线。
  2. 每日 00:05 后刷新页面，确认前一自然日消费已经结算。
  3. 签到功能开放且满足最低消费条件时，点击“今日签到”。
  4. 以页面返回的到账结果为准，可在“签到奖励记录”中再次核对。

积分与余额的区别

  • 消费积分是活跃度记录，不等同于现金余额。
  • 总积分累计保留，昨日积分只对应前一自然日。
  • 签到奖励到账后才进入可用余额。
  • 策略调整按生效日期执行，不回改已结算记录。
  • 失败、取消或已退款消费不会重复产生积分。
  • 异常状态不要连续点击，先刷新奖励记录确认结果。
!
奖励展示不公开后台随机区间

用户页面只展示是否具备资格和最终到账金额。阶梯、随机范围与风控上限仅由管理员维护，避免被篡改或利用。

注册用户发行工具

提链中心把账户余额转换成可独立交付的额度卡

提链 Key 本身就是额度卡卡密。创建者先从自己的余额预充值，购买者收到完整 Key 后无需注册 52Token，即可在额度卡中心激活和使用。

01选择分组

只能选择管理员授权且当前账号有权使用的分组。

02设置金额与数量

批量创建按单张金额乘数量计算，余额不足时整批不生成。

03余额先扣再创建

服务端在同一资金事务中扣款、生成 Key 和写入流水。

04复制并交付

新卡为待激活状态，购买者首次输入完整 Key 后自动激活。

额度换算公式 对外 1x 可用额度 = 单张预充值金额 / 创建时有效分组倍率

例如创建时使用 0.08x 分组，单张预充值 8U，则对外显示 8 / 0.08 = 100U 的 1x 可用额度。

创建一张额度卡

  1. 登录后进入“提链中心”，在创建区选择可用分组。
  2. 填写单张充值金额和创建数量，先核对页面计算的总扣款。
  3. 提交后等待成功结果，再从“我的额度卡”列表复制完整 Key。
  4. 把完整 Key 交付给购买者，提醒其前往 key.52token.org 激活。
  5. 后续需要续费时，由创建者在提链中心找到该 Key 并充值。

状态与可执行操作

状态含义创建者可以做什么
待激活已预充值但购买者尚未在额度卡中心激活复制、充值；零使用时可退款并销毁 Key
使用中已激活且仍有可用额度查看记录、充值，不支持自行退款
欠费最后一笔后扣请求可能使余额低于零，后续请求被拒绝充值覆盖欠费后自动恢复，无需手动启用
冻结管理员暂停该 Key 的调用联系管理员处理，充值不会绕过冻结
已退款或撤销Key 已失效不可再次激活或调用
购买者快速接入

收到额度卡后，无需注册即可查看额度和请求记录

购买者只需要完整 Key。额度卡中心不会提供充值、退款、编辑或创建者资料，这些操作由创建者或管理员处理。

  1. 打开 key.52token.org，确认浏览器地址和 HTTPS 证书正常。
  2. 输入完整额度卡 Key，点击“验证并激活”。连续输错会触发临时安全锁定。
  3. 激活后查看剩余额度、分组名称、Token、缓存、费用、类型和延迟记录。
  4. 从额度详情页复制完整 Key，并按接入教程填写 API Base 和模型名称。
  5. 额度耗尽后联系销售者充值，充值足额后 Key 会自动恢复使用。

分销与自动发货

用清晰额度、自动交付和可查记录建立稳定的销售体验

创建者可以在闲鱼、小红书等渠道销售预充值额度卡。商品描述应聚焦无需注册、额度透明、使用记录可查和售后边界清楚，不使用“永久免费”“绝对稳定”或“官方授权”等无法持续保证的表述。

100U 额度卡的示例账目

创建成本8 元
发行分组0.08x
对外额度100U
销售定价10 元，毛差 2 元

示例按 8 / 0.08 = 100U 换算。实际净收益还应扣除交易平台费用、退款损耗和售后成本。下游额度卡成功产生的消费记录归属创建者账户，符合积分策略的部分会在次日结算为创建者消费积分，以积分中心实际记录为准。

发布商品前的检查清单

  • 先用一张小额卡完成激活和请求测试。
  • 商品规格明确写清 1x 额度，不混用创建成本。
  • 自动发货只发送对应订单的一张完整 Key。
  • 商品主图和公开描述不展示任何真实 Key。
  • 写明数字商品交付后退款和售后处理边界。
  • 保留订单号、交付时间和提链中心资金记录。

文本与内容生成接口

文本接口统一使用 https://api.52token.org。以下是接口契约说明，不是可直接执行的命令。

协议方法与路径鉴权头最小必要字段
ResponsesPOST /v1/responsesAuthorization: Bearer <key>model、input
Chat CompletionsPOST /v1/chat/completionsAuthorization: Bearer <key>model、messages
MessagesPOST /v1/messagesx-api-key: <key>model、max_tokens、messages
Gemini ContentPOST /v1beta/models/{model}:streamGenerateContent?alt=ssex-goog-api-key: <key>contents

通用请求要求

  • JSON 请求必须声明 Content-Type: application/json。
  • model 必须与可用渠道页面显示的模型名完全一致。
  • 长时间文本任务应使用协议支持的流式模式，例如 Responses/Chat 的 stream=true 或 Gemini 的 streamGenerateContent?alt=sse。
  • 非流式请求如果超过边缘网络的无响应等待上限，可能在模型完成前中断，因此不适合作为长任务调用方式。
  • 流式请求由客户端按 SSE 或对应协议消费，不要将中途断开自动视为未请求。
  • 工具调用字段应按客户端协议发送，不要同时混用多种协议的工具结构。

下载GET https://image.52token.org/v1/videos/{task_id}/content获取已完成任务的视频内容

创建任务步骤

  1. 使用 Authorization: Bearer <key> 鉴权，JSON 请求声明 Content-Type: application/json。
  2. 请求体至少包含 model 和 prompt，按模型要求增加时长、分辨率和参考素材。
  3. 建议每个业务任务设置唯一 Idempotency-Key，同一任务恢复时继续使用原值。
  4. 保存创建响应中的平台任务 ID，后续仅用该 ID 查询。

任务状态与轮询

状态含义客户端处理
creating / queued / pending / running任务仍在处理每 5-10 秒查询一次，使用同一任务 ID
completed / succeeded生成完成读取平台返回的视频地址，或请求 /content
failed / cancelled / expired任务终止停止轮询；确认需要重做后再创建新任务
!
不要因为等待时间长而重复创建

高分辨率或含参考素材的视频可能需要较长时间。创建后优先使用原任务 ID 继续查询；反复 POST 会形成多个独立生成任务。

完成后的视频地址

  • 任务成功后，查询响应可能在 url、video_url或结果对象中返回平台地址。
  • 对外可见的完成地址应使用 video.52token.org，地址中不包含上游主机名。
  • 下载地址是短期签名地址，应尽快下载到客户端本地。
  • 视频播放器可按需使用 Range 分段请求；不要把地址作为永久公开链接。

错误、超时与重试

现象处理建议
401 / 403检查密钥是否有效、是否属于当前分组，以及鉴权头是否符合当前协议
402余额或密钥配额不足；图片和视频会在调用前校验可用余额
400检查模型名、必填字段、分辨率、比例和参考素材数量
429按错误响应的等待时间后重试，不要高频并发
5xx / 连接中断文本请求按客户端规则处理；图片和视频若已有任务 ID，必须先查询原任务
视频长时间运行保持 5-10 秒的查询间隔，延长总等待时间，不要重复创建
!
生图和视频不做自动重放

媒体生成可能已被服务端接受。网络超时不等于任务未创建，因此平台不会将这类请求自动重放到另一账号。有任务 ID 时使用查询接口恢复。
